## 3. Cyclic Month Encoding (`eda.ipynb` + `features_daily.csv`)

**Problem:** Raw `month` integer (1–12) treats January and December as maximally distant. A linear model cannot learn that they are seasonally adjacent. This was identified as a root cause of the March baseline's negative test R².

**Fix:** Added two columns to the feature engineering cell and regenerated `features_daily.csv`:

```python
features_df['month_sin'] = np.sin(2 * np.pi * features_df['month'] / 12)
features_df['month_cos'] = np.cos(2 * np.pi * features_df['month'] / 12)
```

`features_daily.csv` is now **1,119 rows × 16 columns** (was 14 columns).

Also added `xgboost>=2.0.0` to `requirements.txt` and ran `brew install libomp` (required by XGBoost on macOS).

## 4. Modeling Notebook (`models.ipynb`) — Full Rebuild

Replaced the March OLS baseline with three models evaluated using **5-fold TimeSeriesSplit cross-validation**.

### Evaluation strategy change

| March baseline | April rebuild |
|---|---|
| Single 80/20 time-ordered split | 5-fold TimeSeriesSplit |
| Test set = summer 2025 only | Test set spans multiple seasons |
| Train R² = 0.79, Test R² = −0.70 | Per-fold results below |
| Raw month integer (1–12) | Cyclic sin/cos for Ridge; raw month for trees |

### Models

**Ridge Regression** (linear features: `month_sin`, `month_cos`, StandardScaler per fold, RidgeCV alpha ∈ [0.1–1000])

**Random Forest** (`n_estimators=300`, `max_depth=8`, `min_samples_leaf=10`, `max_features=0.6`)

**XGBoost** (`n_estimators=300`, `learning_rate=0.05`, `max_depth=4`, `subsample=0.8`, `colsample_bytree=0.8`)

### CV Results

| Model | CV R² (mean) | ± Std | RMSE (pp) | MAE (pp) |
|---|---|---|---|---|
| Ridge | −1.292 | ±2.366 | 2.484 | 2.033 |
| Random Forest | −0.773 | ±1.560 | 2.508 | 2.086 |
| **XGBoost** | **−0.512** | **±0.768** | **2.468** | **1.997** |

**Best model: XGBoost** — highest R², lowest variance, lowest RMSE.

RMSE ≈ 2.47 pp on a target range of 7–27% ≈ 10–12% relative error.

### Why CV R² is negative

Negative R² is not model failure. It reflects **seasonal distribution shift** between training and test folds.

| Test season | Ridge | RF | XGBoost |
|---|---|---|---|
| Spring/Summer (folds 1, 3, 5) | −5.19, −0.51, −1.76 | −3.41, +0.27, −1.00 | −1.79, −0.07, −0.68 |
| Fall/Winter (folds 2, 4) | +0.47, +0.53 | +0.23, +0.03 | +0.06, −0.08 |

Winter test folds consistently achieve near-zero or positive R². Summer test folds go negative because early folds have insufficient training data to have seen a complete annual cycle. Fold 1 trains on only ~6 months (fall/winter 2022–23) then tests on spring/summer — essentially extrapolation.
